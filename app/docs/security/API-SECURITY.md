# API: безопасность перед запуском

Этот этап проверен в локальной изолированной сети Docker, не на production.
Development-БД не использовалась. Compose, CI, frontend и release-конфигурация
не изменялись этим этапом.

## Аутентификация и proxy

POST /api/login: 5 запросов/минуту на нормализованный email + IP, дополнительно
30 запросов/минуту на IP при смене email. POST /api/register: 5 запросов/минуту
на IP. Учитываются и успешные, и невалидные запросы. Ответ 429 содержит Retry-After.
JWT, logout и проверка текущей роли из БД сохранены. Email в ключах лимитера хеширован.

Используется Laravel Request::ip(). Доверенные proxy сейчас не настроены:
произвольные X-Forwarded-For не меняют ключ лимитера. За proxy запросы могут
делить один лимит. До запуска нужно настроить явный список адресов/CIDR
реального proxy, разрешить только необходимые forwarding-заголовки, обеспечить
их перезапись на proxy и исключить прямой публичный доступ к PHP.
Нельзя включать доверие ко всем адресам или произвольному X-Forwarded-For.
Это требует отдельной настройки развёртывания и здесь не применено.
Для нескольких PHP-процессов/реплик лимитер должен использовать общий Redis
или другой общий cache store; array/file на отдельных узлах не подходит.
Распределённый перебор с множества IP требует дополнительного мониторинга/WAF.

## Доступ

Публичны чтение каталога, регистрация и вход. Покупатель получает только свою
корзину и свои заказы. Изменение статуса заказа, запись каталога, отчёты,
список пользователей и смена ролей требуют auth:api + admin.
Регистрация использует только валидированные name/email/password; role теперь
также исключён из User fillable. Смена роли выполняется явным присваиванием в
существующем обработчике с блокировками. JWT не содержит административного claim.
Цена и владелец заказа берутся сервером из БД, привилегированные поля запроса
игнорируются. Существующие проверки владельца сохранены.

Первый администратор: из доверенного интерактивного терминала выполнить
`php artisan auth:create-admin` в окружении приложения. Команда запрашивает имя,
email, скрытый пароль и подтверждение, не принимает пароль через аргументы,
хеширует его стандартным Laravel cast и не повышает роль существующего email.
Пароль: минимум 12 символов, регистры, цифры и спецсимволы. Не использовать
DatabaseSeeder/Test User, tinker с паролем в shell history или публичный маршрут.
Команда не запускалась против development или production. Доступ к CLI и
секретам развёртывания необходимо ограничить отдельно.

## Уточнения контракта валидации

* Цена: сохранены ограничения предыдущего этапа — 0..21474836.47,
  не более двух десятичных знаков (хранение копеек в PostgreSQL integer).
* Вес: 0.001..99.999, до трёх десятичных знаков, соответствует numeric(5,3).
* Количество: целое 1..30 на границе API; существующие более строгие ограничения
  категорий и суммарного количества продолжают действовать.
* Идентификаторы: положительный bigint, не более PHP_INT_MAX на 64-битной PHP.
  Неверный route ID даёт 404 до SQL/model binding, product_id — 422 до exists.
* Каталог: page — целое 1..1000000; размер страницы остаётся 30.
  Административная пагинация сохраняет существующие границы per_page 1..100
  и защиту от переполнения OFFSET.
* delivery_method: delivery, pickup, courier. Сохранён courier, присутствующий
  в существующих интеграционных данных; произвольные строки теперь дают 422.
* Итог заказа свыше 99999999.99 отклоняется с 422 до записи заказа и очистки корзины.
* Login требует строковый пароль и email; пароли на входе ограничены 4096 символами.

Ранее невалидные/неограниченные значения теперь отклоняются намеренно. Схема
БД не менялась, старые записи не переписывались. Необязательные посторонние поля
по-прежнему игнорируются, существующие успешные форматы ответов сохранены.

## Ошибки отчётов

API сохраняет поле error, но выдаёт только локализованное общее сообщение,
включая старые строки с техническими подробностями. Генератор сохраняет
безопасный текст. Ошибки создания и открытия скачивания дают безопасный 503
даже при app.debug=true. Файл открывается до отправки streaming-заголовков.
Логи содержат тип/код исключения, файл/строку и ID отчёта, где он известен;
не содержат сырое сообщение, аргументы, request body, пароли и токены.
Исходное исключение генератора повторно бросается для существующего retry/DLQ.
Ограничение доступа к worker/failed_jobs/логам и их срок хранения остаются
операционной задачей: стандартный queue worker может сохранять исходное исключение.

## MinIO: подготовлено, не применено к развёртыванию

Текущий PHP-контейнер получает MINIO_ROOT_USER/PASSWORD через Compose;
Laravel s3 читает AWS_ACCESS_KEY_ID/SECRET_ACCESS_KEY из окружения/.env.
Сравнение локальных .env/.env.local и app/.env без вывода значений подтвердило,
что AWS-ключи приложения совпадают с root-ключами MinIO. Даже при отдельных
AWS-ключах передача root-секрета PHP избыточна.
Изменение этой передачи требует правки развёртывания и здесь не выполнено.

`minio-app-policy.json` — политика для отдельной идентичности приложения:
GetObject/PutObject/AbortMultipartUpload только reports/reports/* и ListBucket
с ограничением prefix. Первое reports — имя бакета, второе — префикс файлов
существующего ReportStorage. Для другого AWS_BUCKET заменить ARN перед применением.
Нет DeleteObject, управления бакетами/пользователями и доступа вне префикса.
AbortMultipartUpload нужен для отмены загрузки крупных отчётов SDK.

В отдельном этапе оператор должен создать service identity, назначить политику,
передать её ключи через AWS_* в PHP/worker, убрать MINIO_ROOT_* из приложения,
перезапустить процессы, проверить разрешённые операции и запреты, затем
отозвать прежние ключи. Backup/recovery/admin используют отдельную идентичность.
Бакет заранее создаёт оператор; приложение не должно создавать его само.
Политика проверялась на временном MinIO, настройки настоящего MinIO не менялись.

Воспроизводимая проверка политики: на изолированных тестовых сервисах передать
AWS_* ограниченного пользователя и запустить
`MINIO_POLICY_CHECK=1 php tests/Support/minio_policy_check.php` при APP_ENV=testing.
Скрипт пишет reports/security-check.jsonl только в тестовый бакет; проверяет
чтение/запись и запреты удаления, записи/листинга вне префикса и списка бакетов.
Обычный PHPUnit не запускает этот отдельный скрипт автоматически.
